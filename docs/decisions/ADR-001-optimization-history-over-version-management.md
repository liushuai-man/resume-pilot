# ADR-001：以优化历史与恢复替代通用简历版本管理

- 状态：已接受
- 日期：2026-08-12

## 背景

V2.0 原计划提供完整简历版本列表、命名、对比和任意恢复。但用户主要需要的是安全应用 AI 建议、理解修改效果，以及在结果不满意时撤销，而不是像 Git 一样管理多个简历分支。

## 决策

- 保留应用前自动快照，作为底层恢复保障。
- 用户界面展示可理解的优化历史：改了什么、为什么修改、是否采纳、评分如何变化、问题是否解决。
- 支持撤销已应用优化；恢复操作本身也保留当前状态，避免不可逆。
- V2.0 MVP 不提供手动命名版本、版本分支、通用版本树和完整 JSON 差异查看器。
- 不增加独立“版本管理”一级入口；优化历史归属具体简历。

## 影响

阶段 4 调整为“优化历史与恢复”。底层 `ResumeVersion` 继续存在，但只是恢复实现细节；面试需要稳定输入时，应绑定不可变快照或内容哈希，而不是依赖用户可见的版本管理产品。
