# ResumePilot 游客体验与权限边界方案

**状态：** 分阶段实施中  
**适用范围：** 简历、目标岗位、ATS/内容质量、岗位匹配、模拟面试、个人画像  
**目标：** 用户不登录也能理解并走通 ResumePilot 的主要闭环；登录用于留存成果，而不是换取页面访问权。

## 1. 问题定义

当前实现混淆了三件事：页面访问、功能执行和云端持久化。前端虽然允许游客进入部分路由，但目标岗位页在游客态停止加载，模拟面试页直接渲染登录限制卡片；后端岗位、面试、画像接口又统一要求登录。因此实际体验仍然是“先登录，才能了解产品”。

游客体验不应是只读展示，也不应是空壳页面。目标状态是：

> 先让用户完成一次真实任务并得到有价值的结果，再邀请用户登录保存这些结果。

GitHub 登录属于数据归属与同步手段，不属于业务页面的访问门票。

## 2. 设计原则

1. **页面默认开放。** 一级导航和核心工作台不因未登录而跳转登录页，也不显示整页锁定卡片。
2. **先体验，后绑定。** 创建、编辑、分析、面试和查看报告均应有游客路径。
3. **在价值时刻邀请登录。** 只在跨设备保存、历史长期留存、分享等动作发生时邀请登录。
4. **不制造假成功。** “已保存”仅表示云端持久化；游客只能显示“已存到本机”。
5. **游客数据属于用户。** 登录后应迁移游客成果，不得以登录为代价丢弃当前工作。
6. **限制成本，不限制理解。** AI 调用可设置游客额度、频率和样本规模，但必须允许完成至少一个闭环。
7. **提醒克制且可行动。** 不持续用大面积警告打断操作；提醒要说明风险、保存位置和解决方式。

## 3. 身份与数据状态

产品只保留三个运行状态，不再使用含义模糊的“展示模式”。

| 状态 | 身份 | 工作数据 | 典型入口 |
| --- | --- | --- | --- |
| 未选择 | 无 | 无 | 落地页首次访问 |
| 游客工作区 | 浏览器生成的 `guestWorkspaceId` | IndexedDB 本地数据；可选匿名服务端短期会话 | 点击“直接体验”或首次进入业务页 |
| 账号工作区 | GitHub 用户 | PostgreSQL 云端数据 | 登录成功并完成游客数据迁移 |

进入业务页面时自动创建游客工作区，不要求用户先做身份选择。`isGuest` 应表示一种有效工作状态，而不是权限不足状态。

## 4. 功能权限矩阵

| 产品能力 | 游客体验 | 登录用户 | 游客实现策略 |
| --- | --- | --- | --- |
| 浏览全部业务页面 | 完整 | 完整 | 路由不做登录拦截 |
| 新建、编辑、套用模板 | 完整 | 完整 | IndexedDB 本地文档 |
| 导入 PDF/图片 | 支持一次体验 | 完整 | 临时上传，短 TTL，或仅本地解析能力就绪后改为本地 |
| PDF 导出 | 完整 | 完整 | 客户端打印或匿名短期导出接口 |
| JD 创建与岗位画像 | 完整走通至少 1 个岗位 | 完整 | 本地岗位草稿 + 匿名 AI 调用 |
| ATS 结构检查 | 完整 | 完整 | 确定性规则前移到前端或开放匿名计算接口 |
| 内容质量与岗位匹配 | 至少各 1 次 | 按账号额度 | 匿名配额，不要求先保存云端实体 |
| 模拟面试 | 至少完成 1 场短面试 | 完整 | 游客会话 3–5 题，本地记录，匿名 AI 配额 |
| 面试报告 | 完整查看本场报告 | 完整与历史聚合 | 当前报告本地保存；历史聚合需登录后迁移 |
| 个人中心 | 展示本地成果形成的即时画像 | 云端长期画像 | 不展示虚构数据；样本不足时明确来源和样本数 |
| 跨设备同步、长期历史 | 登录引导 | 完整 | 这是账号能力，不是页面能力 |
| 分享链接、团队协作 | 登录引导 | 按产品范围 | 需要稳定数据归属时再要求登录 |

“至少一次”是成本控制下限，不是界面锁定。额度耗尽后保留已有页面、输入和结果，动作按钮显示下次可用时间或登录后继续，不替换整个页面。

## 5. 游客主路径

```text
落地页
  → 直接体验
  → 自动创建游客工作区与一份可编辑示例简历
  → 编辑真实内容或继续使用示例
  → 粘贴 JD / 使用示例 JD
  → 生成岗位画像
  → 运行 ATS、内容质量和岗位匹配
  → 根据建议修改简历
  → 完成 3–5 题模拟面试
  → 查看本场报告与即时能力画像
  → 登录并保存全部成果（推荐，但不强制）
```

每个工作台都提供“使用我的内容”和“载入示例”两条路径。示例不是静态截图，而是与真实组件、真实状态机和相同分析结果结构交互。

## 6. 页面与交互规范

### 6.1 全局导航

- 所有一级导航对游客可点击，不做导航前拦截。
- 右上角显示低干扰状态：“游客 · 已存到本机”。
- 点击该状态展开数据说明和“登录同步”操作，不使用持续占据纵向空间的大警告条。
- 游客访问个人中心时展示本地数据产生的画像；没有样本时提供一键载入示例或开始任务，不显示登录墙。

### 6.2 数据状态文案

只使用下列可验证状态：

| 状态 | 文案 |
| --- | --- |
| 正在写入 IndexedDB | 正在存到本机… |
| IndexedDB 写入成功 | 已存到本机 |
| 云端写入成功 | 已同步到云端 |
| 本地写入失败 | 本机保存失败，请立即导出备份 |
| 本地有变化、尚未完成写入 | 有更改尚未保存 |

禁止游客界面出现“已保存到云端”“完整功能需登录”“仅浏览展示”等不准确文案。

### 6.3 登录邀请时机

推荐出现：

- 用户完成第一份简历或第一份面试报告后；
- 用户点击“跨设备同步”“生成分享链接”“查看长期趋势”；
- 游客 AI 免费额度耗尽后；
- 浏览器存储不可用或空间不足时。

不应出现：

- 点击一级导航时；
- 页面初次加载时；
- 编辑第一个字段之前；
- 用整页卡片替换目标功能时。

邀请使用非阻塞抽屉或结果页内嵌区域，并明确承诺：“登录后保留当前简历、岗位、分析和面试记录”。关闭后继续使用当前页面。

## 7. 本地数据与丢失提醒

### 7.1 存储分层

- `localStorage`：只存主题、布局偏好、游客工作区 ID 和轻量状态。
- `IndexedDB`：简历、JD、岗位画像、分析结果、面试题答、报告与迁移队列。
- 内存：流式输出、暂未提交输入和短生命周期 UI 状态。
- 匿名服务端会话：仅承载 AI 调用和无法在浏览器完成的文件处理，默认 TTL 24 小时，不作为游客长期存储。

建议所有游客实体使用可迁移 ID：`guest:<workspaceId>:<entityType>:<uuid>`。实体包含 `schemaVersion`、`createdAt`、`updatedAt`、`syncState` 和 `source`。

### 7.2 提醒分级

1. **常驻轻提示：** 右上角“游客 · 已存到本机”。
2. **首次成果提示：** 第一次成功保存后提示一次“当前内容只在这台设备上”。
3. **风险提示：** IndexedDB 不可用、写入失败、浏览器存储空间不足时显示不可关闭的错误，并提供 JSON/PDF 导出。
4. **离开提示：** 仅在仍有未写入 IndexedDB 的变更时触发 `beforeunload`；已写入本机的草稿不重复阻拦。
5. **主动备份：** 游客可以导出工作区备份文件，并从备份恢复，不以登录作为唯一防丢手段。

## 8. 登录后的无损迁移

GitHub OAuth 发起前把当前路径、游客工作区 ID 和迁移清单保存到 `sessionStorage`。登录回调完成后：

1. 获取账号云端资产摘要；
2. 读取游客 IndexedDB 迁移队列；
3. 按依赖顺序迁移：简历 → JD/岗位画像 → 分析 → 面试会话/报告；
4. 服务端通过 `guestEntityId + userId` 保证幂等，重复回调不产生副本；
5. 冲突时保留两份并标记“游客草稿”，不静默覆盖云端数据；
6. 全部成功后标记本地实体 `synced`，延迟 7 天清理；
7. 部分失败时继续进入原页面，显示可重试的迁移摘要。

迁移接口建议：

```http
POST /api/guest/migrations
Idempotency-Key: <workspaceId>:<migrationVersion>

{
  "workspaceId": "...",
  "entities": [
    { "guestEntityId": "...", "type": "resume", "schemaVersion": 3, "payload": {} }
  ]
}
```

## 9. 后端权限模型

当前 `authMiddleware` 只能返回“登录用户”或 401，需要拆成两层：

- `optionalIdentityMiddleware`：识别登录 Cookie 或匿名工作区签名，生成 `principal`。
- `requireAccountMiddleware`：只用于跨设备同步、分享、账号配置等真正需要稳定身份的接口。

```ts
type Principal =
  | { kind: 'account'; userId: string }
  | { kind: 'guest'; workspaceId: string; quotaKey: string };
```

业务服务接收 `principal`，不要在控制器中到处判断 `isGuest`。游客 AI 接口必须具备：IP + 工作区双重限流、请求体大小限制、模型白名单、并发限制、内容安全检查和匿名数据 TTL。禁止仅依赖客户端传来的 `workspaceId` 作为可信身份，应由服务端签发 HttpOnly 匿名 Cookie。

对于不需要数据归属的能力，优先设计无实体接口：

```http
POST /api/public/ats/check
POST /api/guest/job-profile/analyze
POST /api/guest/resume/content-quality
POST /api/guest/job-match/analyze
POST /api/guest/interviews
```

请求直接携带当前本地快照，响应由前端写入 IndexedDB。避免为了运行一次分析，先在数据库中创建伪用户和永久业务实体。

## 10. 前端架构调整

1. 删除业务路由上的 `ProtectedRoute`；只保留 OAuth 回调和账号设置类路由保护。
2. 删除 `InterviewPage` 的游客整页 `Lock` 分支和各页面的登录占位卡片。
3. 建立 `WorkspaceRepository` 接口，页面不直接区分本地 API 与云端 API：

```ts
interface WorkspaceRepository {
  listResumes(): Promise<Resume[]>;
  saveResume(resume: Resume): Promise<SaveReceipt>;
  listJobs(): Promise<JobDescription[]>;
  saveInterview(session: InterviewSession): Promise<SaveReceipt>;
}
```

4. 游客注入 `IndexedDbWorkspaceRepository`，登录用户注入 `CloudWorkspaceRepository`。
5. AI 计算单独通过 `AnalysisGateway`，游客和账号只在额度及持久化策略上不同，页面组件复用同一状态机。
6. 为游客初始化一组版本化示例资产：一份简历、一份 JD、对应岗位画像和一份可重放的报告。用户修改后即成为自己的本地副本。

## 11. 实施顺序

### 阶段 A：去除登录墙

- 所有业务路由和页面开放；删除整页限制卡片。
- 提供版本化示例数据，使简历、岗位、面试、画像页面都有可交互内容。
- 统一“已存到本机/已同步到云端”状态文案。

### 阶段 B：本地工作区

- 引入 IndexedDB repository 与 schema migration。
- 简历、JD、分析、面试、报告走统一本地数据层。
- 实现备份导入导出与真正基于 dirty state 的离开提醒。

### 阶段 C：匿名真实能力

- 后端增加匿名 principal、签名 Cookie、TTL 和配额。
- 开放游客 ATS、岗位画像、匹配和短面试闭环。
- 加入成本、滥用和失败降级监控。

### 阶段 D：登录迁移

- OAuth 前保存迁移上下文。
- 实现幂等批量迁移、冲突处理、失败重试和迁移结果提示。
- 登录成功后回到原任务位置，而不是固定跳转首页。

## 12. 验收标准

- 新浏览器从落地页到进入任一一级页面，全程不出现强制登录跳转。
- 游客能完成“编辑简历 → 分析 JD → 查看匹配 → 完成短面试 → 查看报告”的闭环。
- 游客页面不出现整页登录锁、空白工作台或因 401 产生的错误通知风暴。
- 游客刷新页面后，本机数据和当前任务状态可恢复。
- 已写入 IndexedDB 的游客数据离开页面时不重复弹出丢失确认。
- 登录后所有游客实体可迁移，关系保持完整，重复回调不产生重复数据。
- 登出后账号数据不泄露到游客工作区；原游客数据若仍在保留期内可恢复。
- AI 游客额度耗尽时保留页面、输入和已有结果，仅限制新的高成本计算。
- 浏览器存储不可用时，在用户开始大量输入前明确提示，并提供导出方案。

## 13. 当前实现差距

- `JobCenterPage` 在游客态直接停止加载，缺少本地/示例数据源。
- `InterviewPage` 在游客态返回整页登录卡片，未复用真实面试状态机。
- 岗位、面试、画像后端路由全部使用强制认证中间件。
- 当前游客草稿主要依赖 Zustand `localStorage`，不适合多实体和大体积报告。
- 游客登录后没有完整的关系数据迁移流程。
- 当前顶部游客警告条过强，且 `beforeunload` 未基于真实 dirty state。

后续实现必须以本方案的“功能优先开放、数据按身份分层”为准，不再通过增加更多登录判断修补游客体验。

### 2026-08-26 · 数据生命周期与登录迁移

- 游客实体默认按最后写入时间保留 30 天；应用启动时执行轻量过期清理。
- 工作区最多保留 200 个实体、约 15 MB，超限时按“旧面试 → 旧分析 → 旧岗位 → 简历”顺序回收。
- 页面进入后台或关闭时释放内存降级缓存；所有 IndexedDB 连接均在事务结束后关闭。
- 游客状态菜单提供显式“清空这台设备上的游客数据”，操作前必须确认。
- 登录后自动迁移简历、JD/岗位画像、内容质量、岗位匹配和面试报告；关系 ID 在事务内重建。
- 服务端以 `userId + entityType + guestEntityId` 生成稳定 UUID 并使用 upsert，OAuth 回调或网络重试不会产生重复记录。
- 成功迁移的本地实体标记为 `synced`，继续保留 7 天后清理；部分失败实体保持 `local` 并在后续进入工作台时重试。
- ATS 游客结果属于本地确定性计算结果，当前云端没有对应持久化表，因此不迁移；登录后可由同一简历重新计算。
