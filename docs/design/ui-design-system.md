# ResumePilot V2.0 UI 设计系统

**状态：** 待审核，批准前不批量修改页面。  
**适用范围：** 展示页、认证、管理页、编辑器、岗位工作台、模拟面试与报告。  
**用户品牌：** 统一显示“AI 简历助手”；`ResumePilot` 仅保留为工程名。

## 1. 设计命题

产品面向需要针对目标岗位准备简历并训练面试的求职者。界面的首要任务不是渲染“AI 感”，而是让用户始终知道：当前处理哪份简历、面向哪个岗位、结论依据是什么、下一步做什么。

视觉方向定义为 **求职证据工作台**：借用招聘审阅、简历批注和材料归档的秩序感，强调证据、定位、状态与行动。避免蓝紫渐变、发光机器人、大面积玻璃拟态、无意义数据大屏和过度圆角。

设计原则：

1. 先定上下文，再给操作。
2. 一个页面只保留一个主操作。
3. ATS、匹配、优化和面试结论必须靠近原文依据。
4. 浏览器返回、页面返回和面包屑回到相同业务上下文。
5. 主题只改变品牌色，不改变成功、警告、错误等语义色。

## 2. 视觉系统

### 2.1 色彩

| Token | 默认值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F4F7F6` | 略带冷绿的纸张灰背景 |
| `surface` | `#FFFFFF` | 导航、卡片、弹层 |
| `ink` | `#17211D` | 主文字 |
| `muted` | `#66736D` | 次级信息 |
| `brand` | `#176B52` | 主按钮、焦点、当前导航 |
| `brand-soft` | `#E3F2EC` | 选中区域浅底 |
| `line` | `#D8E1DD` | 边框、分隔和证据轨道 |
| `evidence` | `#C9792B` | JD 引用和证据提示 |

固定语义色：成功 `#198754`、警告 `#B86B16`、错误 `#C23B3B`、信息 `#2D67B2`。所有正文与交互满足 WCAG AA 对比度。

### 2.2 字体与尺度

- 中文标题与正文：`Noto Sans SC`，回退 `Microsoft YaHei UI, sans-serif`。
- 英文品牌与首页主标题：`Manrope`，克制使用。
- 分数、字段定位和评价器版本：`IBM Plex Mono`。
- 正文 `15px / 1.65`；页面标题 `32px / 700`；区块标题 `20px / 650`；辅助信息不小于 `12px`。

### 2.3 形状与布局

- 主卡片圆角 `10px`，按钮 `8px`，标签 `6px`，不把所有控件做成胶囊。
- 卡片以 `1px` 边框分层，默认无阴影；只在悬浮和弹层使用轻阴影。
- 间距序列：`4 / 8 / 12 / 16 / 24 / 32 / 48 / 64`。
- 普通页面最大宽度 `1200px`，岗位工作台和报告 `1440px`，长文本阅读列 `720px`。

### 2.4 识别性元素：证据轨道

本产品唯一的强识别元素是“证据轨道”：用细竖线串联岗位要求、简历原文、AI 结论与用户操作。它表达真实关系，不作装饰。

```text
● 岗位要求        Java / Spring Boot
│
● 简历证据        “负责服务端接口开发……”
│
◆ AI 结论         证据不足：缺少规模与结果
│
○ 用户操作        补充事实 / 暂不处理
```

只有存在两项以上关联证据时才使用轨道，普通列表不强行套用。

## 3. 导航与路由

### 3.1 路由边界

```text
公开区
/                          产品展示页
/auth/login                登录页

登录工作区
/resumes                   我的简历
/resumes/:id/edit          简历编辑器
/resumes/:id/optimizations 优化历史
/jobs                      目标岗位
/interviews                模拟面试准备/进行状态机
/interviews/history        面试记录
/interviews/results/:id    面试报告
/settings/appearance       外观设置
```

- `/` 不再重定向到 `/resumes`，固定为公开展示页。
- 未登录访问私有路由时保存完整 URL，跳转 `/auth/login?returnTo=...`。
- 登录成功优先返回 `returnTo`；没有目标时进入 `/resumes`。
- 已登录用户在展示页点击“进入工作台”；未登录用户点击“开始使用”进入登录。
- 旧路由只做一次 `replace` 重定向，不产生多级跳转链。

### 3.2 全局导航栏

桌面端顶部固定导航，高 `64px`：

```text
┌─────────────────────────────────────────────────────────────────────┐
│ [文档勾形图标] AI简历助手 │ 我的简历 目标岗位 模拟面试 面试记录 │ ◐ 头像 │
└─────────────────────────────────────────────────────────────────────┘
```

- 最左为单色“折角文档 + 一笔勾选/航线”SVG 与中文“AI 简历助手”，不用字母缩写、机器人或闪光星。
- 品牌点击行为：未登录回 `/`，已登录回 `/resumes`。
- 一级导航只保留四项；模型选择移入头像菜单的“模型设置”。
- 头像菜单包含账户、外观、模型设置和退出登录。
- 当前项使用主题色文字与 `2px` 下划线，不使用整块胶囊背景。
- 移动端保留品牌，四项任务导航转为底部栏，账户和设置进入头像抽屉。

### 3.3 页面级导航

- 二级页面显示面包屑，例如“我的简历 / 优化历史”。
- 编辑器和面试使用任务栏：左侧文字返回、中间当前对象、右侧唯一主操作。
- 返回按钮必须写明目标，如“返回我的简历”，不能只放箭头。
- 从详情返回列表时恢复筛选和滚动位置；进入新详情时置顶。

## 4. 产品展示页

展示页的唯一任务是让新用户理解求职闭环并开始使用，不提前要求登录。

首屏文案：

- 主标题：**从岗位要求，到一份有证据的简历。**
- 说明：粘贴 JD，检查简历证据，逐条确认优化，并用同一岗位标准完成模拟面试。
- 主按钮：`开始使用` → `/auth/login`。
- 次按钮：`查看工作流程` → 页面内流程区。

首屏右侧不放虚构数据仪表盘，展示真实的“JD 要求—简历证据—改进建议”交互样例，并首次呈现证据轨道。

内容顺序：

1. 岗位画像 → 简历诊断 → 安全优化 → 模拟面试 → 报告复盘。
2. 三项可信承诺：结论有依据、修改需确认、可以安全撤销。
3. 目标岗位、简历优化、面试报告的真实界面示例。
4. 隐私与边界：不编造经历、低置信度待确认、用户掌控最终内容。
5. 末尾 CTA：`用 GitHub 登录并开始`。

唯一的进入动画是证据轨道从 JD 节点延伸至简历节点；遵守 `prefers-reduced-motion`，不添加零散滚动特效。

## 5. 登录与权限

- 登录页与展示页共享品牌和色板，不显示工作区导航。
- 明确按钮为“使用 GitHub 登录”，并说明读取的信息。
- 登录失败说明原因与下一步，重试不丢失 `returnTo`。
- 展示页和登录页公开；简历、岗位、面试、报告与设置均受保护。
- 鉴权期间显示统一骨架，不能先显示私有内容再闪回登录页。

## 6. 主题与基础个性化

第一版提供三个预设主题，不开放任意取色器：

| 名称 | `brand` | `brand-soft` |
| --- | --- | --- |
| 松石绿（默认） | `#176B52` | `#E3F2EC` |
| 深海蓝 | `#285C9D` | `#E6EEF8` |
| 紫藤灰 | `#66558F` | `#EEEAF6` |

基础设置：

- 主题色三选一，实时预览。
- 明暗模式先提供“浅色 / 跟随系统”；完整深色模式在组件验收后开放。
- 内容密度：舒适 / 紧凑，只影响列表与工作台，不压缩点击区域。
- 减少动效：跟随系统并允许手动覆盖。

未登录设置保存在 `localStorage`；登录后先用本地值即时渲染，再同步用户设置。全部由 CSS variables 驱动，组件中不得散落硬编码主题色。

## 7. 核心页面

### 7.1 我的简历

- 卡片突出名称、目标方向、最近更新和唯一主操作“继续编辑”。
- 预览、优化历史、导出、删除进入次操作区或菜单，不放五个等权圆形图标。
- 新建简历使用正常卡片，不用尺寸突兀的大虚线占位。

### 7.2 目标岗位

- 桌面采用“岗位列表 `280px` + 当前岗位工作区”。
- 顶部固定岗位名、公司、画像状态和当前简历。
- JD、岗位画像、ATS、内容质量、岗位匹配、分析记录使用二级页签，不增加路由深度。
- 每个分数标注评价类型和更新时间，不制造来源不明的总分。

### 7.3 简历编辑器

- 顶部任务栏：返回我的简历 / 标题与保存状态 / 预览、导出。
- 左栏内容编辑，中间 A4 预览，右栏诊断建议；无任务时右栏可收起。
- AI 建议顺序固定为依据、原文、建议、用户操作。
- 保存状态只使用“保存中 / 已保存 / 保存失败”。

### 7.4 优化历史

- 时间线优先显示来源、动作、原因与结果；前后文本可展开。
- 撤销事件与原事件视觉关联，不作为另一条普通优化。
- 没有后评分时显示“尚未重新评价”并提供重新评价入口。

### 7.5 模拟面试与报告

- 阶段 5 负责业务流程，本文件只规定呈现。
- 准备态选择岗位、简历和模式；开始后冻结上下文。
- 进行态保持单一答题主区域，回答后不插入评分或 AI 点评。
- 简历、JD 等辅助材料使用左侧抽屉，默认不挤压答题区域。
- 报告用证据轨道连接能力维度、问题、回答证据与建议。

## 8. 组件与状态

优先建立：`BrandMark`、`PublicHeader`、`WorkspaceHeader`、`TaskHeader`、`PageShell`、`PageHeader`、`Breadcrumbs`、`Toolbar`、`EvidenceRail`、`EmptyState`、`ErrorState`、`Skeleton`、`ConfirmDialog`、`ThemeProvider`。

- 按钮描述结果：“创建简历”“开始面试”“撤销优化”，不用泛化的“确定”“提交”。
- 空状态解释为何为空并给一个下一步；错误状态说明数据是否保留及恢复方式。
- 图标按钮必须有 Tooltip 和辅助文本；焦点统一为 `2px brand` 外环。
- 最小点击区域 `40 × 40px`；页面在 200% 缩放下仍可使用。

## 10. 实施顺序与验收

方案批准后按独立 UI 切片实施，不与阶段 5 面试业务逻辑混做：

1. Token、字体、`ThemeProvider`、品牌图标与基础组件。
2. 公开展示页、登录页、权限回跳与公开/私有边界。
3. 全局导航、头像菜单、外观设置与移动端导航。
4. 我的简历与优化历史。
5. 目标岗位工作台。
6. 简历编辑器。
7. 模拟面试与报告外观；业务行为仍按阶段 5 独立验收。

每个切片必须完成桌面 `1440 / 1280`、移动 `390` 截图审核，键盘操作，三色主题切换，200% 缩放，空/错/加载状态和生产构建。未审核页面不得自行创造新的颜色、阴影、圆角或导航模式。

## 11. 本轮不做

- 不在方案批准前批量改页面。
- 不建设皮肤商城、自定义任意颜色或背景图片。
- 不把模型选择器继续放在一级导航。
- 不借 UI 重构改变 ATS、优化或面试规则。
- 第一轮不承诺完整深色模式。

## 12. 待审核决策

3. `/` 改为公开展示页，登录后的默认工作台为 `/resumes`。
4. 主题第一版使用三种预设色，不开放任意取色器；深色模式延后。
