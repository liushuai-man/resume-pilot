# ResumePilot 开发会话归档（2026-08-10）

## 当前目标

将 ResumePilot 从简单 AI 简历工具升级为完整求职辅助系统，形成“简历 → JD → 评价 → 优化 → 面试 → 报告”的闭环。开发遵循 `docs/roadmap/v2-roadmap.md`，每次只推进一个阶段或一个可验收纵向切片。

## 已完成的重要设计

- 建立 V2.0 独立开发路线图，并允许根据验证结果持续调整。
- 新增 `docs/design/information-architecture.md`。
- 一级信息架构调整为：我的简历、目标岗位、模拟面试、面试记录。
- `/interviews` 直接进入面试状态机，不再经过宣传式中转页。
- ATS/岗位分析记录归目标岗位；简历优化版本归具体简历；面试报告归面试记录。
- 管理页面统一页面头部、宽度、标题、卡片和按钮风格；编辑器和面试使用精简任务工具栏。

## 阶段 0：简历基础能力

- 编辑器、首页和面试预览复用统一 React 简历预览内核。
- PDF 导出改为 Puppeteer 打印专用只读预览路由。
- 专业技能改为用户自由填写的分类与技能描述，不再使用熟练度能量条。
- 分页和预览仍需要继续积累真实模板回归样本。

## 阶段 1：JD 与 JobProfile

- 完成 JD 保存、列表、删除和“保存并分析”加载流程。
- 使用用户默认模型抽取岗位名称、职级、行业、职责、必备能力、加分项和关键词。
- JobProfile 使用严格 JSON、Zod 校验和 JD 原文 evidence 校验。
- 支持 draft、confirmed、superseded 状态与版本切换；历史版本只读。
- 保存模型、Prompt、Parser 和 JobProfile 版本。
- 低置信度字段提示用户确认。

## 阶段 2：评价体系（进行中）

评价链已拆为四层，禁止混成来源不明的总分：

1. ATS 结构分：确定性规则，检查机器可读性、字段结构和明显输入异常。
2. 内容质量分：模型检查连贯性、信息有效性、证据具体性、上下文一致性和专业性。
3. 事实核验：院校、公司等通过权威数据源或标准库核验；未命中只能标记待确认。
4. JD 岗位匹配：基于已确认 JobProfile，检查能力覆盖、关键词证据、职责相关性和职级匹配。

### ATS 结构初检

- 使用 `ats-rules-v3-additive` 加分制，从 0 分开始。
- 页面展示六个结构维度和字段级问题。
- 明显重复、占位词和键盘乱码不得分，但字符规则不冒充语义评价。
- ATS 回归测试 5/5 通过。

### 内容质量评价 Agent

- 已实现五维严格 JSON Prompt 和 Zod 解析。
- 每个问题绑定 `section / item / field`、字段原文、理由、建议、严重级别和置信度。
- 模型引用证据必须能在对应简历字段中定位，否则拒绝结果。
- 低于 70% 置信度的结论标记为“待确认”。
- 不允许模型判断学校、公司或经历真假。
- 保存分析快照、简历更新时间、内容哈希、模型、Prompt 和评价器版本。
- 简历更新后旧报告标记为过期。
- 内容质量解析测试 3/3 通过。

2. 使用真实默认模型和固定异常简历集校准内容质量 Agent。
