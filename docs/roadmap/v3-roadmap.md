# ResumePilot 3.0 实施路线图

**文档性质：** 动态执行文档  
**产品范围：** [3.0 产品设计与范围基线](../product/v3-product-spec.md)  
**集中验收：** [3.0 验收清单](../testing/v3-acceptance-checklist.md)

## 1. 实施原则

- 以可使用的纵向闭环拆分，不按前端、后端、数据库或 Agent 横向拆分交付
- 每个阶段先固定业务不变量、数据归属和失败恢复，再扩展自动化程度
- 复用现有 V2 的 JobProfile、诊断、优化、版本、面试流水线和能力画像能力
- 每次只保持一个主要里程碑处于实施状态；未经验证的后续设计可调整
- 新表和新服务必须有明确查询路径、权限边界、过期规则与删除策略
- 每个阶段完成自动检查、人工主路径和至少一个失败场景后才能进入下一阶段
- 不把接入某个具体模型供应商作为产品完成标准

## 2. 阶段总览

| 阶段 | 交付目标 | 依赖 | 退出条件 |
| --- | --- | --- | --- |
| M0 基线与观测 | 冻结 V2 基线，建立 3.0 指标与迁移保护 | V2 集中验收 | 基线可复现，3.0 变更可度量 |
| M1 岗位工作空间 | 统一岗位、简历、分析、面试上下文 | M0 | 一个岗位闭环的数据归属清晰可用 |
| M2 行动闭环 | 把诊断和面试弱项转成可完成、可验证行动 | M1 | 行动完成后可证明结果或明确未解决 |
| M3 成长画像 | 形成可追溯的跨场次能力趋势 | M1、M2 | 趋势有证据、版本和样本边界 |
| M4 按轮语音面试 | 完成可靠语音问答、转写确认和双维报告 | M1、M3 | 主路径、降级、删除和故障恢复通过 |
| M5 发布加固 | 可观测性、隐私、性能、可访问性和试用验收 | M0–M4 | 满足 3.0 发布定义 |

M3 与 M4 的技术预研可并行，但 M4 不应在面试报告证据模型稳定前进入正式开发。

## 3. M0：基线、事件与迁移保护

### 目标

确保 3.0 建设不会破坏 V2 已完成的诊断、优化恢复与模拟面试能力，并让后续产品指标可计算。

### 工作项

- 执行并记录 V2 集中验收，列出已知缺陷与暂缓项
- 为核心闭环定义最小事件字典：创建岗位、确认画像、关联简历、开始/完成行动、应用/撤销建议、开始/完成面试、查看报告
- 统一请求关联 ID、AI 任务 ID 和流水线阶段日志
- 为数据库迁移建立向前迁移、回滚预案和测试数据备份流程
- 明确性能与成本基线：普通接口、AI 分析、面试生成、报告生成
- 建立 3.0 feature flag，允许按功能关闭工作空间、行动和语音能力

### 退出标准

- V2 自动检查全部通过，未通过项有责任边界和处理决定
- 事件不记录简历、JD、回答或密钥正文；事件重复上报可去重
- 生产旧数据迁移可在副本环境演练，失败不会破坏原记录
- 至少能按用户和岗位关联一次完整流程的日志与事件

## 4. M1：岗位工作空间与求职工作台

### 目标

让用户围绕一个目标岗位管理专属简历、分析、优化与面试，而不是在孤立模块之间手动寻找上下文。

### 最小纵向切片

1. 从现有目标岗位创建或进入工作空间。
2. 关联一份当前简历；切换简历时明确下游报告过期影响。
3. 在同一空间展示 JobProfile 状态、三类诊断、优化记录和面试记录。
4. 工作台展示当前目标和最多 3 个下一步行动入口；M1 可先使用确定性状态规则生成入口，不建立完整行动表。
5. 从工作台进入任务，完成后返回同一岗位上下文。

### 数据与接口

- 设计 `ApplicationWorkspace` 或等价关联模型；优先引用现有 Job 和 Resume，不复制正文
- 定义一个用户是否允许同一岗位关联多份简历；首版只允许一个当前简历，可保留历史关联事件
- 所有聚合接口服务端校验用户所有权，避免前端拼接跨用户资源
- 对删除岗位、删除简历、撤销关联和删除面试结果定义明确行为

### 退出标准

- 新老数据都能进入工作空间；没有关联简历时不会产生无来源分析
- 在两个岗位之间切换时，简历、画像、分析和面试记录不会串联
- 修改简历或确认新画像后，受影响的报告在工作台和详情页一致标记过期
- 删除/取消关联经过确认，且不会留下可访问的孤儿入口
- 桌面端完整主路径和移动端基本查看路径通过浏览器验收

## 5. M2：优先行动与效果验证

### 目标

让系统从“展示问题”升级为“指导用户完成最值得做的下一步，并验证效果”。

### 最小纵向切片

1. 从一个最新的 ATS、内容质量或岗位匹配问题创建行动。
2. 行动展示原因、证据、目标位置、建议操作和完成条件。
3. 用户可开始、完成、忽略或因上游变化看到行动过期。
4. 完成行动触发相应确定性检查或重新分析。
5. 页面展示“已解决、未解决、待确认或验证失败”，不只展示分数变化。

### 后续切片

- 从面试薄弱项创建专项训练行动
- 用户手动创建提醒型行动
- 基于规则计算优先级：阻断程度、岗位重要性、证据质量、预计成本、新鲜度
- 工作台限制同时展示最多 3 个优先行动，避免制造任务焦虑

### 退出标准

- 每个系统行动都能追溯到正式报告或面试证据
- 重复请求不创建重复行动；上游版本改变时旧行动自动变为 `stale`
- AI 建议应用仍使用现有快照、并发保护、撤销和重新评分机制
- 缺少事实的任务不会通过模型自动补齐为“完成”
- 行动完成后有机器验证或明确的用户确认记录
- 可计算行动开始率、完成率、问题解决率和过期率

## 6. M3：证据化成长画像

### 目标

把多次面试从历史列表升级为可信的能力成长记录，并为下一轮训练提供依据。

### 工作项

- 统一能力维度标识、Rubric 版本和 JobProfile 映射
- 每条能力评价绑定场次、题目、回答证据和置信度
- 定义有效场次与最小样本量；不足时展示样本不足
- 展示趋势、近期变化、持续薄弱项和证据抽屉
- 从薄弱项创建专项面试行动，下一场计划优先覆盖该能力
- 处理 Rubric 或画像版本变化导致的不可比断点

### 退出标准

- 删除一场面试后，聚合结果可重复计算且不保留幽灵证据
- 不同 JobProfile 的能力数据默认隔离
- 任一分数都能追溯到有效题目和回答，无法定位的结果不进入正式画像
- 少样本、低置信度和版本不可比状态均有明确展示
- 完成专项训练后，可以看到该行动对应的新证据，但不承诺一次训练必然涨分

## 7. M4：按轮语音模拟面试

### 目标

在不牺牲可靠性、可控性和隐私的前提下，让用户完成更接近真实表达压力的语音面试。

### 技术预研门禁

正式开发前使用合成数据比较候选 ASR/TTS 服务：

- 中文、英文及中英混合转写准确性
- 首包和完整转写延迟
- 浏览器音频格式兼容性
- 单场成本、速率限制和数据保留条款
- 服务失败时能否安全重试或切换供应商

预研只产生 ADR 和可替换 Provider 接口，不直接把供应商字段扩散到业务模型。

### 最小纵向切片

1. 进入语音模式前完成麦克风、播放和网络检查。
2. AI 问题显示文字并进行语音播报；TTS 失败不阻塞回答。
3. 用户开始、暂停、重录和提交单题录音；显示时长与上传状态。
4. 系统生成转写，用户确认或修改后才提交正式回答。
5. 刷新页面恢复到安全状态，不自动继续录音或重复提交答案。
6. 报告分别展示内容评价与语音指标，生成专项行动。
7. 用户删除原始音频后，播放入口消失，文字记录按策略保留。

### 安全与运维

- 浏览器、API 和对象存储均限制格式、大小、时长和 MIME 类型
- 音频上传使用不可预测资源标识和用户鉴权；不得形成永久公开链接
- 定义临时分片清理、失败上传清理和账户删除流程
- ASR/TTS 调用记录供应商、模型、耗时、成本和错误码，但不记录音频正文
- 默认不做连续后台监听；录音必须由清晰的用户操作开始和结束

### 退出标准

- Chrome/Edge 最新稳定版完成整场语音面试；至少一种移动浏览器完成首题
- 拒绝权限、录音中断、上传失败、转写失败、TTS 失败和刷新恢复均有可用路径
- 转写修正前后文本分开保存，内容评分只读取用户确认版本
- 内容分与语音表现分分开展示；报告不包含情绪、人格、外貌或诚信推断
- 原始音频删除可验证，删除后旧链接和播放接口不可访问
- 同一答案重复提交不会生成重复问答或重复报告

## 8. M5：发布加固与真实用户验证

### 工作项

- 完成集中验收中的自动、浏览器、真实模型和故障注入测试
- 优化首屏、长任务和音频链路性能，记录基线与回归阈值
- 完成键盘操作、标签、对比度、错误提示和移动端关键路径检查
- 提供隐私说明、第三方模型提示、音频删除和账户数据删除入口
- 建立 AI 失败率、成本、队列积压、转写失败和删除失败告警
- 邀请目标用户完成真实 JD、简历优化和语音面试闭环，记录观察而非只收集主观评价
- 对阻断与高风险问题清零；中低风险问题进入发布说明与后续路线

### 退出标准

- [3.0 验收清单](../testing/v3-acceptance-checklist.md) 的发布门禁全部通过
- 至少一轮真实用户试用覆盖新用户和已有数据用户
- 数据迁移、功能关闭、供应商故障和音频删除均有演练记录
- 产品负责人按产品基线第 9 节逐条签署发布结果

## 9. 候选池：不阻塞 3.0 发布

- 实时全双工语音与用户打断
- 视频面试和虚拟背景
- 求职日历、提醒通知与第三方任务管理集成
- 职位抓取、邮件解析和自动投递
- 多人协作、导师点评和公开分享
- 订阅、额度、团队套餐和推荐增长
- 原生移动应用

候选项进入正式路线前必须说明目标用户、替代方案、数据边界、预期指标和停止条件。

## 10. 每轮迭代记录模板

| 项目 | 内容 |
| --- | --- |
| 里程碑/切片 | Mx 与本轮纵向切片 |
| 用户问题 | 本轮要解决的具体阻碍 |
| 最小实现 | 实际交付范围及明确未做内容 |
| 数据与迁移 | 新对象、版本、过期和删除影响 |
| 验证样本 | JD、简历、场次、浏览器与失败场景 |
| 结果指标 | 完成率、解决率、失败率、耗时和成本 |
| 发现的问题 | 产品、模型、性能、安全与可访问性问题 |
| 调整决定 | 保留、修改、降级、推迟或删除 |
| 下一轮目标 | 下一项最值得验证的能力 |
